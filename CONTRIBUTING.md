# Contributing to HansenAI

Thanks for wanting to help build this. HansenAI gets better when people who actually do security work shape it.

## Before you start

- Read the [README](README.md) and [docs/vision.md](docs/vision.md) so your contribution points the same direction the project does.
- Open an issue to discuss anything substantial before writing a lot of code. A short conversation saves a long rewrite.

## Ground rules

1. **Authorized-use first.** Contributions must keep the platform aligned with authorized, defensive, and educational use. Features whose main purpose is to harm systems without permission will be declined.
2. **Explain the why.** This is a teaching platform. Code and content that help people understand *why* something works are worth more here than clever one-liners that don't.
3. **Don't break the scope guarantees.** Anything that touches the execute path must respect authorization gating and audit logging.

## How to contribute

- Fork the repo and branch from `main`.
- Keep pull requests focused — one idea per PR.
- Write a clear description: what it does, why, and how you tested it.
- Add or update docs and examples when behavior changes.

## Kinds of contributions we want

- Learning content: labs, walkthroughs, explanations.
- Guidance logic: methodology, checklists, step reasoning.
- Tooling and integrations for the execute engine.
- Bug reports, security reports (see [SECURITY.md](SECURITY.md)), and documentation fixes.

## Code of conduct

Participation is covered by our [Code of Conduct](CODE_OF_CONDUCT.md). Be the kind of person others want to learn alongside.
