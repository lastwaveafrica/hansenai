# Security & Responsible Use

HansenAI is a cybersecurity platform. That cuts both ways: the project itself must be secure, and the people using it must use it responsibly. This document covers both.

## Responsible use

HansenAI exists for **authorized** security work:

- Penetration testing and red teaming with written permission.
- Defensive security, detection engineering, and incident response.
- Education, training labs, and self-study on systems you own or are explicitly allowed to use.
- CTF competitions and academic/security research.

The platform's execute-capable features require an explicit statement of authorization and keep an audit trail of what was run. Using HansenAI to access, disrupt, or damage systems you are not authorized to touch is against the terms of this project and, in most places, against the law. Don't.

If a feature could cause harm with no legitimate defensive or educational purpose, it does not belong here, and we will not build it.

## Reporting a vulnerability in HansenAI

If you find a security issue in HansenAI itself, please report it privately rather than opening a public issue.

- Use GitHub's **private vulnerability reporting** on this repository, or
- Contact the maintainer through the address listed on the repository profile.

Please include enough detail to reproduce, the affected version or commit, and the impact as you understand it. We'll acknowledge, investigate, and coordinate a fix and disclosure timeline with you.

## Supported versions

Until the first tagged release, the `main` branch is the supported version. Supported-version policy will be published alongside the first release.
